# Анализатор приказов: PDF, МКБ, УКД и ЭРДБ

MVP 0.2: загрузка и разбор PDF, нормализация МКБ, выделение простых УКД и загрузка справочника ЭРДБ. Данные обрабатываются локально, внешние API и LLM не используются. Сопоставление приказов со справочником — следующий этап.

## Быстрый запуск на Windows

Нужен Python 3.11 или новее. Если `venv` уже создан, первый шаг пропустите.

```powershell
python -m venv venv
venv\Scripts\python.exe -m pip install -e ".[ui,dev]"
venv\Scripts\python.exe -m streamlit run app.py
```

После установки можно запускать двойным щелчком по `run.bat`. Откройте http://localhost:8501, выберите PDF и нажмите **«Загрузить и разобрать»**. Результат можно посмотреть по страницам, проверить исходные ячейки и скачать в JSON/TXT. Приказы 149 и 75 определяются по первой странице; для других документов есть универсальный профиль.

## Этапы MVP

| Этап | Что сделано | Результат |
|---|---|---|
| 1. Загрузка PDF | Проверка файла, SHA-256, чтение всех страниц, текст, таблицы с границами, координаты ячеек | `LoadedPDF`, команда `load` |
| 2. Парсер | Базовые поля 149/75, разделы, продолжения ячеек, ссылки на источник, замечания | `ParseResult`, команда `parse` |
| 3. МКБ | Кириллица/латиница, пробелы, списки, диапазоны одного уровня, включения/исключения, проверка иерархии | `icd`, команда `normalize` |
| 4. УКД | Классы, стадии, степень/тяжесть, типы, состояния после событий, отрицания, связи с периодичностью | `ukd`, вкладка «МКБ и УКД» |
| 5. ЭРДБ | Четыре листа XLSX, аудит ключей, поиск и прямые связи МКБ → группа → УКД | `erdb.json`, команда `erdb` |

Работает с текстовыми PDF до 50 МБ и 500 страниц. Скан без текстового слоя возвращает понятную ошибку; пустая страница в смешанном документе отмечается замечанием. Удаляются отдельные счётчики страниц и распознанный водяной знак «Әділет»; исходный текст сохраняется до очистки.

**149:** текстовые пункты приказа/правил; приложения 1–3 к Правилам — заболевания, исходные фрагменты МКБ, периодичность наблюдения, обследования и сроки. Приложения 4–5 сохраняются как отдельные строки сестринской классификации и сегментации, без превращения их кодов в МКБ.

**75:** все шесть разделов перечня; заболевание, исходный МКБ, категория, показания, название продукта, форма и исходный АТХ. Объединённые ячейки наследуют контекст с указанием строки-источника. Неоднозначные переносы между страницами отмечаются `needs_review`.

**Универсальный профиль:** текст и таблицы без предположений о предметной структуре.

В этот MVP не входят OCR, полноценное сопоставление приказов/УКД, LLM и итоговый медицинский отчёт. Дата редакции автоматически не назначается. Сложные подпункты и склейки требуют проверки. `parsed` означает технический разбор; полнота предметного извлечения обозначена `not_verified`.

## Как пользоваться новыми функциями

В поле **«PDF документы — можно выбрать несколько»** выберите оба приказа (149 и 75), удерживая Ctrl, либо добавьте второй через **Add files**. Для каждого файла можно отдельно выбрать профиль; по умолчанию он определяется автоматически. Оставьте включённым флажок **«Нормализовать МКБ и выделить УКД»** и нажмите **«Загрузить и разобрать»**. Файлы обрабатываются последовательно; ошибка одного не мешает обработке остальных.

Переключайте готовые результаты через **«Результат документа»**. Для каждого сохраняются собственные страницы, записи, замечания и файлы JSON/TXT. Во вкладке **«МКБ и УКД»** показаны коды, условия с цитатами и страницами, а также фильтр записей для проверки. В раскрываемом JSON доступны исправления, исходные условия и связи с периодичностью. Изменение набора PDF или профилей сбрасывает результаты на экране; сохранённые папки остаются. Справочник ЭРДБ остаётся общим и загружается независимо. Одновременная загрузка двух приказов пока не запускает их сравнение.

Ниже находится независимый блок **«Справочник УКД ЭРДБ»**: выберите `UKD-actualnyi.xlsx` и нажмите **«Загрузить справочник»**. По коду МКБ можно посмотреть прямые связи, по названию — найти УКД. Аудит показывает пропуски, дубликаты и спорные коды. Результат скачивается в JSON; точная копия XLSX сохраняется в каталоге запуска. Смена выбранного файла сбрасывает предыдущий результат в интерфейсе.

МКБ проверяется по встроенному структурному каталогу **WHO ICD-10 2019, COVID-expanded**, 12 221 код: [официальный источник ВОЗ](https://icdcdn.who.int/icd10/index.html). Совпадение с национальной редакцией Казахстана не подтверждено. Отсутствие кода в этой версии означает «требует проверки», а не доказательство ошибочного кода. Происхождение и SHA-256 каталога сохранены в JSON.

Диапазоны раскрываются только по реально существующим кодам одного уровня. Смешанные диапазоны вроде `D45–D47.9` сохраняются для проверки. `J44.0` входит в `J44` по иерархии; обратное неверно. Включения не сужают базовый код, исключения учитываются отдельно. При неразобранной части выражения проверка покрытия возвращает неопределённость.

УКД извлекаются правилами: `III–IV ФК` даёт два допустимых класса; «все стадии» относится к стадиям; степень, стадия и тяжесть остаются отдельными признаками. Для сложного текста сохраняются вся исходная формулировка и статус `needs_review`. Простое извлечение признаков не означает полной интерпретации показаний. Идентификаторы понятий нужны для группировки, они **не являются ID справочника ЭРДБ**.

ЭРДБ строит только связи, прямо указанные в XLSX. Связь для `J45` не переносится автоматически на `J45.0`. Повторяющиеся названия не объединяются; записи с неоднозначными ключами сохраняются в аудите и исключаются из связей. Проверка структуры ключей и проверка кода по версии ВОЗ — разные признаки.

## Работа из командной строки

Только загрузить текст и таблицы:

```powershell
venv\Scripts\python.exe -m pipeline load "C:\path\document.pdf"
```

Загрузить и разобрать:

```powershell
venv\Scripts\python.exe -m pipeline parse "C:\path\document.pdf"
venv\Scripts\python.exe -m pipeline parse "C:\path\document.pdf" --profile 149 --output data
venv\Scripts\python.exe -m pipeline parse "C:\path\document.pdf" --profile generic
venv\Scripts\python.exe -m pipeline parse "C:\path\document.pdf" --no-enrich
venv\Scripts\python.exe -m pipeline normalize "В18, включая В18.0. В18.1"
venv\Scripts\python.exe -m pipeline enrich "data\previous-run\result.json" --output data
venv\Scripts\python.exe -m pipeline erdb "C:\path\UKD-actualnyi.xlsx" --icd J45 --output data
```

Доступные профили: `auto`, `149`, `75`, `generic`. Ключ `--strict` у команды `parse` возвращает код 2 при замечаниях парсера, МКБ или УКД, сохраняя результат. `normalize` возвращает 2 для `needs_review`. Код 0 — успешная обработка, код 1 — ошибка входного файла или сохранения. `enrich` требует исходный `source.pdf` рядом с JSON и не извлекает PDF повторно. `erdb` сохраняет результат даже при замечаниях аудита.

Каждый запуск создаёт отдельную папку `data/<sha256-первые-12>-<идентификатор>/`:

```text
source.pdf       точная копия исходного файла
manifest.json    время запуска, хеш и перечень файлов
text.txt         очищенный текст с номерами страниц
result.json      полный результат parse
loaded.json      вместо result.json при команде load
```

В JSON `pages` содержит исходный/очищенный текст, таблицы, ячейки и их координаты; `order149_rows` / `order75_rows` — распознанные записи; `other_rows` — остальные строки; `clauses` / `notes` — пункты и примечания; `issues` — замечания с номерами страниц и строк. `source_refs` позволяют вернуться к исходной строке. Нумерация страниц и строк начинается с 1; координаты PDF — в пунктах, начало отсчёта сверху слева.

`summary.raw_table_rows` и `summary.accounted_table_rows` проверяют учёт извлечённых строк. Их равенство не доказывает правильность содержания или полноту обнаружения таблиц. Таблицы без видимых границ могут остаться только в тексте.

Каталог `data/` исключён из Git. Повторный разбор не перезаписывает предыдущий запуск. Приложение предназначено для локальной работы одного пользователя и слушает `127.0.0.1`.

`manifest.json` записывается последним. Если запись прервалась, папка без корректного манифеста считается незавершённой. Каталоги не переименовываются после записи: это позволяет сохранять результат и при работающем наблюдателе файлов на Windows.

## Где менять код

```text
app.py                простой интерфейс Streamlit
pipeline/
  loader.py           PDF → страницы, текст, таблицы
  parser.py           страницы/таблицы → записи 149/75
  icd.py              выражения МКБ, иерархия и проверка покрытия
  ukd.py              признаки УКД, выражения и цитаты
  enrichment.py       подключение МКБ/УКД к строкам парсера
  erdb.py             XLSX → справочник, аудит и индексы
  resources/          версия каталога МКБ с источником и хешем
  models.py           структуры данных обоих этапов
  storage.py          сохранение результата и исходного PDF
  __main__.py         команды load, parse, normalize, enrich и erdb
tests/
  test_pipeline.py    загрузка, разбор и сохранение
  test_app.py         интерфейс: загрузка, результат, ошибки
  smoke_sources.py    проверка на трёх исходных приказах
  smoke_enrichment.py проверка нового этапа на исходных приказах и XLSX
```

Парсер не зависит от Streamlit: его можно использовать из CLI или будущего API. Для работы только через CLI достаточно `pip install -e .`.

## Проверки

```powershell
venv\Scripts\python.exe -m unittest discover -s tests -v
venv\Scripts\python.exe tests\smoke_sources.py --input-dir "C:\Users\rusla\Downloads\Telegram Desktop" --output data\smoke
venv\Scripts\python.exe tests\smoke_enrichment.py --runs data\smoke --xlsx "C:\Users\rusla\Downloads\Telegram Desktop\UKD-actualnyi.xlsx" --output data\stage2
venv\Scripts\python.exe -m coverage run --branch --source=pipeline.icd -m unittest discover -s tests -p test_icd.py
venv\Scripts\python.exe -m coverage report -m
```

Автоматические тесты проверяют PDF, наследование, диапазоны/исключения МКБ, условия УКД, связи/ошибки XLSX, сохранность исходников и интерфейс. Smoke-скрипты используют ваши исходные файлы; их копии не включены в репозиторий. Результаты прогонов описаны в `docs/verification.md` и `docs/stage2.md`.
